# 接口与数据模型

## 云函数调用约定

```javascript
app.request({
  url: 'room/getRoomInfo',
  loading: '加载中',
  data: {
    room_id: 1
  },
  success(res) {},
  error(res) {},
  fail(err) {}
})
```

`utils/request.js` 保留原页面回调模型，但内部使用 `wx.cloud.callFunction`：

```text
name: musicApp
data.action: 原业务动作名
data.payload: 页面业务参数
```

## 统一响应模型

客户端假定所有 API 返回：

```text
{
  code: Number,
  msg: String,
  data: Any
}
```

| 业务码 | 客户端处理 |
| --- | --- |
| `200` | 调用业务 `success` |
| `401` | 调用自定义登录处理或跳转登录页 |
| `403` | 权限不足 |
| `422` | 参数校验失败 |
| 其他 | 调用 `error` 或显示统一错误弹窗 |

## API 清单

以下清单根据当前客户端调用整理。

### 用户接口

| 接口 | 用途 |
| --- | --- |
| `weapp/wxAppLogin` | 校验头像，创建新用户或恢复并更新当前 OPENID 对应用户 |
| `user/getmyinfo` | 按可信 OPENID 静默查询已有用户，不自动创建 |
| `user/updateMyInfo` | 更新用户资料 |

### 房间接口

| 接口 | 用途 |
| --- | --- |
| `room/getRoomInfo` | 获取当前房间信息 |
| `room/getSearchPrompts` | 获取房间搜索提示词 |
| `room/updateSearchPrompts` | 房主管理房间搜索提示词 |

### 应用接口

| 接口 | 用途 |
| --- | --- |
| `app/getRealtimeState` | 一次返回默认房间和初始历史消息 |

### 歌曲接口

| 接口 | 用途 |
| --- | --- |
| `song/search` | 搜索歌曲 |
| `song/addSong` | 加入播放队列 |
| `song/addMySong` | 收藏歌曲 |
| `song/deleteMySong` | 删除收藏 |
| `song/mySongList` | 分页获取歌曲收藏（`page` 参数，每页 30 条） |
| `song/songList` | 获取房间播放队列 |
| `song/playSong` | 立即播放（仅房主） |
| `song/push` | 歌曲置顶（仅房主） |
| `song/remove` | 移除队列歌曲（房主或点歌人） |
| `song/pass` | 切歌（任意登录用户，校验队列项一致性） |
| `song/autoPass` | 播放资源失效时自动切歌（系统行为） |
| `song/ended` | 报告当前歌曲自然结束并自动推进队列 |
| `song/refill` | 手动触发自动补歌（目标 1~5 首，默认 3 首） |
| `song/getUrl` | 解析歌曲实际播放地址 |
| `song/getLrc` | 获取歌词 |

歌曲对象包含 `source` 字段，取值为 `netease`、`tencent`、`kugou` 或 `wydt`。播放地址和歌词请求均按 `source` 路由到对应平台接口（网易云走 `meting.mikus.ink`，其余走 `api.i-meto.com`）；当前没有备用回退接口。

### 消息接口

| 接口 | 用途 |
| --- | --- |
| `message/getMessageList` | 获取历史消息 |
| `message/send` | 发送文字、图片或语音，可携带引用消息 ID |
| `message/back` | 撤回消息 |
| `message/clear` | 清空房间历史 |

### 网易云与 QQ 资源接口

`pages/song/select.js`、`pages/song/user-playlists.js` 和 `pages/song/playlist.js` 通过 `utils/jusicWsApi.js` 使用 jusic-serve WebSocket 通道：

| 页面能力 | destination | 响应类型 |
| --- | --- | --- |
| 搜索网易云歌单 | `/music/searchsonglist`，`source=wy` | `SEARCH_SONGLIST` |
| 搜索网易云用户 | `/music/searchuser`，`source=wy` | `SEARCH_USER` |
| 获取用户公开歌单 | `/music/searchsonglist`，`source=wy_user` | `SEARCH_SONGLIST` |
| 获取歌单歌曲 | `/music/search`，`name=*歌单 ID`、`source=wy` | `SEARCH` |
| 搜索 QQ 歌单 | `/music/searchsonglist`，`source=qq` | `SEARCH_SONGLIST` |
| 获取 QQ 用户歌单 | `/music/searchsonglist`，`source=qq_user` | `SEARCH_SONGLIST` |
| 获取 QQ 歌单歌曲 | `/music/search`，`name=*dissid`、`source=qq` | `SEARCH` |

封装层负责 SockJS 开放帧、STOMP `CONNECT`/`CONNECTED` 握手、请求串行化、超时和错误处理，并将响应转换为页面统一结构。歌曲进入歌单详情页后，继续复用 `song/addSong`、`song/addMySong` 和 `song/playSong`；QQ 歌曲播放地址由云函数按 `songmid` 动态解析。

### 附件接口

| 接口 | 用途 |
| --- | --- |
| `attach/search` | 保留的动作占位，固定返回空列表 |

聊天图片、语音和头像不经过云函数动作，直接上传云存储。

## 实时协议

客户端通过云数据库 `watch` 监听：

- `messages` 中 `room_id = 1` 的消息变化。
- `rooms` 中 `room_id = 1` 的当前歌曲变化。

客户端具有登录后读取权限，但不允许直接写数据库；所有写操作通过云函数进行。

## 文件上传

聊天图片、语音和头像使用 `wx.cloud.uploadFile`。数据库保存 `cloud://` 文件 ID，语音消息同时保存毫秒时长。

## 隐式数据模型

项目没有类型定义，以下字段根据客户端访问归纳。

### 用户 User

| 字段 | 含义 |
| --- | --- |
| `_id` / `user_id` | 云数据库用户文档 ID |
| `user_name` | 昵称 |
| `user_head` | 头像地址 |
| `user_sex` | 性别 |
| `user_remark` | 个性签名 |
| `profile_completed` | 是否已完善资料 |

`_openid` 只保存在服务端用户文档中，不包含在客户端用户对象里。

### 房间 Room

| 字段 | 含义 |
| --- | --- |
| `room_id` | 固定为 `1` |
| `room_name` | 房间名称 |
| `room_user` | 唯一房主用户 ID；首位创建默认房间的用户 |
| `room_type` | 房间类型 |
| `room_notice` | 房间公告 |
| `room_public` | 公开或加密设置 |
| `room_addsong` | 点歌权限 |
| `room_sendmsg` | 发言权限 |
| `room_playone` | 播放模式 |
| `search_prompts` | 房主配置的搜索提示词数组，最多 20 个 |
| `current_song` | 当前播放队列项 |
| `backup_songs` | 自动补歌的备用歌曲缓存，最多 10 首 |
| `refill_status` | 自动补歌执行状态 |
| `refill_lock_until` | 自动补歌并发锁截止时间戳（15 秒） |
| `refill_lock_token` | 自动补歌锁令牌 |
| `auto_refill_paused` | 队列排空后的暂停标记 |

播放队列不足时，云函数 `refillQueue` 按「用户收藏 → `backup_songs` 缓存 → `search_prompts` 搜索」顺序补充可播放歌曲，候选歌曲须通过播放地址解析验证。歌曲自然播放结束后，客户端调用 `song/ended`；任意登录用户可调用 `song/pass` 切歌；播放资源失效时调用 `song/autoPass`。队列没有下一首时执行自动补歌流程，也可通过定时触发器 `refillPlaybackQueue` 周期性补充。

### 歌曲 Song

| 字段 | 含义 |
| --- | --- |
| `mid` | 歌曲媒体 ID |
| `source` | 音乐平台：`netease`、`tencent`、`kugou` 或 `wydt` |
| `name` | 歌曲名 |
| `singer` | 歌手 |
| `pic` | 封面 |
| `url` | HTTPS 或云文件播放地址 |
| `lrc` | 歌词数组 |

### 消息 Message

| 字段 | 含义 |
| --- | --- |
| `type` | `text`、`img` 或 `voice` |
| `content` | 消息内容 |
| `user` | 发送用户 |
| `message_id` | 消息 ID |
| `message_time` | 消息时间 |
| `resource` | 图片或语音云文件 ID |
| `duration` | 语音时长，单位毫秒 |
| `reply` | 被引用消息的最小快照 |
| `loading` | 本地临时消息标记 |

### 网易云歌单 Playlist

| 字段 | 含义 |
| --- | --- |
| `id` | 网易云歌单 ID |
| `name` | 歌单名称 |
| `cover` | 歌单封面地址 |
| `creatorId` | 创建者 ID |
| `creatorName` | 创建者昵称 |
| `trackCount` | 歌曲数量 |
| `playCount` | 播放量 |
| `description` | 歌单描述 |
| `source` | 固定为 `netease` |

### 网易云用户 NeteaseUser

| 字段 | 含义 |
| --- | --- |
| `id` | 网易云用户 ID |
| `name` | 用户昵称 |
| `avatar` | 用户头像地址 |
| `signature` | 用户签名 |
| `playlistCount` | 公开歌单数量 |
| `followerCount` | 粉丝数量 |
| `source` | 固定为 `netease` |

`jusicWsApi.js` 会将 jusic-serve 返回的网易云原始字段转换为以上结构，页面不直接依赖原始响应字段。

云数据库消息文档使用 `payload` 保存展示结构，并保存 `created_timestamp` 供排序和友好时间显示。

客户端发送引用时只提交 `reply_to`。云函数读取原消息后生成 `reply`，其中仅保存消息 ID、类型、文字摘要和发送者昵称，不复制完整原消息。

## 鉴权流程

1. 应用使用 `config/cloud.js` 中的显式环境 ID 初始化 `wx.cloud`。
2. 客户端调用 `musicApp` 云函数，不传 OPENID。
3. 云函数通过 `cloud.getWXContext()` 获取可信 OPENID。
4. 云函数根据 OPENID 查询或创建用户。
5. 数据库写操作在云函数中执行，客户端不能伪造其他用户身份。

## 缓存策略

- 消息只保存在页面内存中，最多保留 `historyMax = 20` 条。
- 用户和房间同时存在页面状态与全局状态两份副本。
- 云数据库是业务数据的唯一持久化来源。
