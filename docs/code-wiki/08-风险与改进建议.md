# 风险与改进建议

## 当前阻塞项

### 第三方音乐服务依赖

所有平台的歌曲、歌单、用户和电台搜索，以及播放直链，都依赖 jusic-serve WebSocket（`/music/search`、`/music/songlist`、`/music/searchuser`、`/music/pick`）；网易云歌词依赖 `music.163.com` 官方歌词接口。播放直链带签名和时效，失效后客户端会重新点播一次，仍失败再自动切歌。生产发布前应验证真机播放、WebSocket 连接、歌词接口和签名直链可用性。

需要持续关注：

- 搜索、播放地址、歌词和 WebSocket 请求参数是否发生变化。
- 第三方服务的鉴权方式、限流策略和成功与失败响应。
- 播放地址、歌词地址和图片地址的有效期、重定向规则及 HTTPS 兼容性。
- 音乐资源的版权、地区限制和合法使用授权。
- 搜索和播放直链都依赖单一 jusic-serve 服务，服务故障会导致所有平台无法搜索和点歌；歌词依赖网易云官方接口，接口异常时歌词为空。

## 云资源风险

### 集合和索引不会由源码自动创建

仓库提供规则和索引定义文件（位于 `cloudfunctions/musicApp/`），但云环境仍需实际创建集合与索引。缺少复合索引会导致历史消息或播放队列查询失败。

### 数据库监听成本

首页持续监听 `messages` 和 `rooms`。活跃用户增多后，应监控读次数、监听连接数和消息保留策略。

建议增加消息归档、分页游标和按时间清理策略。

### 默认房间并发创建

首次请求并发到达时，多个云函数可能同时尝试创建默认房间。`room_id` 唯一索引可以防止重复，但应在部署前确保索引已生效。

### 云函数超时限制

云函数默认 3 秒执行上限。自动补歌已不再解析播放地址，网易云歌词请求设置了 2 秒超时和 30 分钟缓存；若后续在云函数内增加外部请求，应调大超时时间或改为异步任务。

### 自动补歌与用户收藏耦合

自动补歌优先使用当前触发用户的收藏，不同用户触发时补充结果偏向各自的收藏口味；收藏为空时才回退到房间缓存和客户端通过 WS 搜索的提示词候选。可考虑房间级共享收藏池或加权策略。

## 安全风险

### 客户端读取范围

当前规则允许登录用户读取集合，以支持数据库监听。应为每个集合配置精确权限，避免客户端读取不需要的用户隐私字段。

### 管理操作权限

各操作在云函数中的权限校验：切歌对所有登录用户开放（仅校验队列项一致性）；立即播放、置顶、清空消息和提示词管理仅限房主；移除队列歌曲限房主或点歌人；撤回消息限发送者或房主。切歌权限放宽后应关注恶意连续切歌风险，当前靠 `queue_id`/`mid`/`source` 一致性校验防止误切新歌。

### 第三方播放地址

云函数限制歌曲 URL 为 HTTPS 或云文件地址，但仍需验证来源授权、有效期、防盗链和重定向行为。

## 架构风险

### 单云函数体积增长

`musicApp` 统一入口便于迁移，但随着业务增加会变得难以维护。建议后续拆分为用户、消息、歌曲领域模块，仍可保留单入口路由。

### 首页职责过重

首页仍同时管理聊天、实时监听、播放器、歌词、导航和 UI 状态。建议拆分消息服务、播放器服务和监听生命周期管理器。

### 状态重复

用户与房间同时存在于页面 `data` 和 `app.globalData`。建议定义统一更新函数，防止页面与全局状态不一致。

### 页面实现模式不统一

部分路由使用 `Page`，部分使用 `Component`。应统一页面规范，只对真正可复用视图使用组件。

## 可靠性风险

### 云函数请求仍是回调模型

`utils/request.js` 为兼容旧页面保留回调接口。复杂业务可逐步增加 Promise 接口、超时提示和请求去重。

### 上传逻辑重复

头像和聊天图片分别调用 `wx.cloud.uploadFile`。建议抽取统一上传模块，统一扩展名、大小限制、压缩和错误处理。

### 自动化验证缺失

仓库仍缺少单元测试、集成测试、数据库模拟、lint 和 CI/CD。优先为云函数校验器、权限判断和队列切换补充测试。

## 推荐演进顺序

1. 获取音乐 API 文档并完成搜索、播放地址和歌词适配。
2. 在云环境创建集合、规则和索引并完成端到端验证。
3. 收紧各集合的客户端读取权限并验证房主权限矩阵。
4. 为消息、引用和播放队列补充自动化测试。
5. 拆分云函数和首页职责，统一状态更新入口。
6. 增加云函数测试、核心流程自动化和发布检查。
